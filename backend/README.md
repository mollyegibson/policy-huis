# Backend

The question API and the agent loop, the same for every city: it answers each question from the MCP servers in its directory and streams the answer to the browser app. The design is the [Agent Loop Plan](../docs/plans/agent-loop.md).

| Path | Contents |
|---|---|
| `config/servers.yaml` | The server directory: each MCP server's name, URL and tool prefix |
| `config/agent.yaml` | The model, loop, tool and API settings (not yet written; its values are provisional until spikes S1 and S2) |
| `src/config/` | Schemas that decode both files; the backend stops at startup on any invalid field |
| `src/tools/` | One long-lived MCP client per server (`McpConnections.ts`), reconnected in the background when a server is down; each request's merged toolkit (`TurnToolkit.ts`) |
| `src/api/QuestionsHandler.ts` | `POST /api/v1/questions`: admission, the turn's prompt and tools, the event stream with keepalives, `Complete`, and the trace write |
| `src/model/ModelLayer.ts` | The `LanguageModel` for the selected model configuration |
| `src/Server.ts`, `src/main.ts` | Configuration, migrations at startup, and the HTTP server on `BACKEND_PORT` |
| `prompts/` | The versioned system prompt |
| `src/loop/` | The agent loop (`AgentLoop.ts`), its events, error classes and user messages, and the context budget |
| `src/trace/` | The fold that turns a question's events into its trace |
| `src/db/` | The `app` schema as Drizzle tables, and the migration runner |
| `drizzle/` | SQL migrations generated by `yarn db:generate` (`drizzle-kit generate`) from `src/db/schema.ts`; applied migrations never change |
| `drizzle.config.ts` | Drizzle Kit's settings |
| `test/` | Configuration decoding; the loop against a scripted model (`test/support/ScriptedModel.ts`); the trace fold; MCP connections against real test MCP servers over HTTP (`test/support/TestMcpServer.ts`); the question API through `HttpApiClient` |
